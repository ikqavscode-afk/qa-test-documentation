# Чек-лист ретеста после исправлений

Краткий порядок проверки, когда разработчики исправили дефекты. Интерактивная версия с галочками — в [чек-листе тестировщика](https://ikqavscode-afk.github.io/qa-test-documentation/) (вкладка «Ретест»).

## 1. Подготовка
- [ ] Получена новая сборка, зафиксирована её версия
- [ ] Список исправленных багов сверен с реестром

## 2. Ретест багов (сначала Critical)
- [ ] По каждому исправленному багу выполнены его шаги воспроизведения
- [ ] Фактический результат совпадает с ожидаемым → статус «Проверено», Issue закрыт
- [ ] Результат не совпал с ожидаемым → баг переоткрыт с комментарием

## 3. Регрессия вокруг исправлений
- [ ] Сценарий «успешное бронирование» от адресов до окна «Машина забронирована»
- [ ] Окна «Добавление прав», «Способ оплаты», «Добавление карты» открываются и закрываются
- [ ] Кнопка «Забронировать» — тексты и действия во всех комбинациях
- [ ] Иконки машин на карте: показ, клик, ориентация

## 4. Окружения
- [ ] Проверено в Firefox 1920×1080 и в Y-браузере 800×600

## 5. Закрытие
- [ ] Ранее пропущенные и заблокированные проверки выполнены
- [ ] Обновлены статусы и метрики, пересобран отчёт о готовности
- [ ] Новые найденные дефекты оформлены отдельными баг-репортами
