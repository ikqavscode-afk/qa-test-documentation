# Оракул: как отличить баг от задуманного поведения

Оракул — источник, по которому мы решаем, каким должен быть результат. Мнемоника **FEW HICCUPS**:

| Буква | Источник | Вопрос |
|---|---|---|
| F | Familiarity | Знакомо ли поведение по другим продуктам? |
| E | Explainability | Можно ли объяснить такое поведение? |
| W | World | Соответствует ли реальному миру? |
| H | History | Как продукт вёл себя раньше? |
| I | Image | Соответствует ли имиджу продукта? |
| C | Claims | Что заявлено в требованиях? |
| C | Comparable products | Как у аналогов? |
| U | User's desires | Чего ждёт пользователь? |
| P | Product / Purpose | Согласуется ли с остальным продуктом и целью? |
| S | Statutes | Стандарты и нормы |

## Примеры из проекта
| Наблюдение | Оракулы | Вывод |
|---|---|---|
| Поле «Часы» принимает «24» | World, Claims | Баг ЯМ-Т16-Б2 |
| Пустое поле «Минуты» не даёт ошибку | Claims, User's desires | Баг ЯМ-Т45-Б5 |
| Поле «Откуда»: текст ошибки про «время» вместо «адреса» | Claims, Explainability | Баг ЯМ-Т50-Б8 |
